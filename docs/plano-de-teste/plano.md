# Plano de Teste

O Plano de Teste é um documento que organiza e define como serão realizados os testes de um projeto, sistema, aplicativo, produto ou processo.

Seu principal objetivo é garantir que tudo funcione corretamente, identificar falhas e verificar se o resultado atende aos requisitos e às expectativas antes de ser aprovado ou colocado em produção.

## 1. Para que serve um Plano de Teste?

Ele serve para:

- Identificar problemas: encontrar erros e falhas antes que afetem os usuários.
- Organizar os testes: definir o que será testado, quando e por quem.
- Definir responsabilidades: estabelecer quem executará e acompanhará os testes.
- Estabelecer critérios: determinar o que significa um teste aprovado ou reprovado.
- Reduzir riscos: evitar problemas depois da implantação ou entrega.

## 2. Como funciona um Plano de Teste?

Normalmente, funciona em etapas:

1. Definição dos objetivos
   Identificar o que precisa ser testado e qual resultado se espera.
2. Definição do escopo
   Determinar quais funcionalidades, processos ou requisitos serão avaliados.
3. Elaboração dos cenários de teste
   Criar situações que serão utilizadas para verificar o funcionamento.
4. Execução dos testes
   Realizar os testes e registrar os resultados encontrados.
5. Registro das falhas
   Documentar erros, comportamentos inesperados e necessidades de correção.
6. Validação e aprovação
   Verificar se os problemas foram resolvidos e se os critérios de aprovação foram atendidos.

## 3. Exemplo prático

Imagine que uma empresa desenvolveu um sistema de cadastro de clientes.

O Plano de Teste poderia ser assim:

| Item | O que será testado |
| --- | --- |
| Cadastro | Se permite cadastrar clientes |
| Nome | Se aceita nomes corretamente |
| E-mail | Se valida e-mails inválidos |
| Senha | Se exige os critérios definidos |
| Salvamento | Se os dados ficam registrados |
| Exclusão | Se permite excluir um cadastro |

Exemplo de um caso de teste:

- Objetivo: verificar se o cadastro funciona.
- Ação: preencher os campos e clicar em Salvar.
- Resultado esperado: o sistema deve cadastrar o cliente e apresentar uma mensagem de sucesso.
- Resultado obtido: cliente cadastrado corretamente.
- Status: Aprovado.

## 4. O que deve conter um Plano de Teste?

Geralmente, um documento completo contém:

1. Identificação do projeto.
2. Objetivos dos testes.
3. Escopo (o que será testado).
4. Requisitos e funcionalidades.
5. Cenários e casos de teste.
6. Responsáveis pela execução.
7. Ambiente e ferramentas utilizadas.
8. Cronograma.
9. Critérios de aprovação e reprovação.
10. Relatório dos resultados.

Esses elementos seguem conceitos utilizados em boas práticas de testes de software, como as referências do ISTQB.

## 5. Resumindo

O Plano de Teste funciona como um roteiro: antes de testar, a equipe planeja; durante os testes, executa e registra; depois, avalia os resultados e verifica se tudo está funcionando como deveria.
